## Findings

### MINOR / NIT
- **MINOR — pandas_ta/volatility/inrange_count.py:97-101 (and docs/InrangeCountMeasured.md §G and "What this port does NOT establish")** — The docstring says the column is "NaN on the first `length` bars (the envelope is not full)", which implies a full envelope after that. Because of `min_periods=1`, that does not hold when the data starts with NaNs. The reviewer ran it with 19 leading NaN highs and lows: bar 20 fires against a 1-bar envelope (it reads 0.0). The reverse case is also left out. After a run of `length` or more bad highs (bars 25..49 tested), bar 50 has valid prices and still comes out NaN, because its envelope is empty. The docstring lists NaN only for the head and for a bar whose own high or low is bad. No section of the script measures either case, and no test covers them.
  - Fix: Add a §G row to docs/measure_inrange_count.py for "leading 19 NaN → first fired bar, envelope size" and one for "25-bar NaN run → first valid bar after it is NaN". Pin both in tests/test_inrange_count.py. Then extend the docstring's NaN paragraph to: "...and on a bar whose prior `length` bars are all bad; after leading NaNs the first fired bars use a partial envelope."
- **MINOR — tests/test_inrange_count.py:446 (`test_gate_d_scale_at_extreme_price_levels`)** — `assert _bit_equal(base, _oracle(*_hl(_walk())))` compares the column at level 1e-6, 1e+6 and 1e+100 with the oracle at level 100. That asserts bit-equality under the inexact rescales ×1e-8, ×1e4 and ×1e98. Docstring item 4 of the same file says the tests deliberately do not assert bit-equality for inexact factors. The test contradicts the file's own stated policy. §D of the script also never prints this comparison, so the assertion has no number in the receipt behind it.
  - Fix: Compare against the oracle at the same level: `_bit_equal(base, _oracle(*_hl(frame)))`. If you want to keep the cross-level check, add a "level L vs level 100: bit-equal" line to §D, report it in the receipt §D, and reword docstring item 4 so it says this is asserted.
- **MINOR — tests/test_inrange_count.py:56 and :31-33; docs/InrangeCountMeasured.md:179** — The test module says "Every number above is printed by `python docs/measure_inrange_count.py`", but "0 of 299 on a 300-bar walk" is not printed by any section (§B only sweeps N=1500). Receipt §M also states "`df.ta` accessors 370", and `section_M` does not print that figure. Both break the repo rule that every count corresponds to a run of the named script.
  - Fix: Add to `section_B` a 300-bar walk sweep that prints "caught 0 of 299". Add to `section_M` a print of the accessor count, computed the same way tests/test_readme_counts.py counts it. Alternatively, reword both sentences so they name the test that measures the figure.
- **NIT — pandas_ta/volatility/inrange_count.py:36-37** — The comment says an infinite high "would ... make every bar 'inside'". That overstates it: `+inf` only makes the `high < hh` half always true, and the `low > ll` half still decides. Under CLAUDE.md, a sentence containing "every" needs a run behind it, and the measured effect (§G: 30 vs 28 later bars moved) does not show every bar going inside.
  - Fix: Change it to "would sit in the envelope for `length` bars and make every bar pass the high test".
