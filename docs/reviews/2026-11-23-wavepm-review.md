### MINOR / NIT
- **MINOR — tests/test_wavepm.py:30-31** — The docstring says `mean-lead` is caught 0 times on `flat` because the flat frame's "mean never changes under the futures that keep it flat". That reason is wrong: the futures scale every bar from j onward, so the series is not kept flat. The real reason is that before j, sigma = 0, so r = 0 and rms = 0. Every bar before j is therefore NaN whatever the mean reads, which is also why `flat` fires nowhere.
  - Fix: Replace it with "(`mean-lead` 0 on `flat`: sigma = 0 before the split, so r = rms = 0 and every bar before the split is NaN whatever mu reads)".
- **NIT — docs/WavepmMeasured.md §W / Z** — The receipt quotes "8 ms" and "33 ms" as exact numbers. The reviewer's full run printed 10 ms and 34–35 ms. The receipt does say these are machine-dependent, but the exact digits still read as reproducible.
  - Fix: Write "about 10 ms / about 35 ms on this machine (varies run to run)", or print a range in §Z and quote the range.

## Summary

The math, wiring and tests are solid. The reviewer ran `tests/test_wavepm.py` with the readme-count, wiring and altport2 suites: 197 passed, 3 skipped. They re-ran every measure-script section (all on synthetic data), and A1, A4, B, C, D, F, G, L, M and W reproduce digit for digit. The five touch points are present, and the accessor forwards `length`, `lookback` and `offset` under the right keywords. Gate B uses real read-off mutants, and Gate D has the x8/x64 bit-identical and x10/x3.7 tolerance checks with matching NaN masks. The 113-bar NaN hole, the tanh(10) bound and the ddof cancellation were checked and are correct. A flat stretch after movement correctly gives NaN rather than a rolling-sum residue. Two problems block it. First, the port skips the one thing the issue says needs a human: reading finta's source and citing its lines. The disclosure is clear, but Gate A as run only checks the module against an oracle written from the same issue text, and the ship-status lines say only Gate E is owed. Second, the receipt says every figure comes from the script, yet it contains a number from a pre-port screen the script cannot produce. Fix both by citing finta or downgrading Gate A to owed, and by deleting or reproducing the 0.5502 figure.

Not checked by the reviewer: the full repo suite and the Backtesting suite (Gate F), and the code of finta and ProRealCode, which they did not see.
