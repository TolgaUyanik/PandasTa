# Task port-132 — PandasTa issue #132, C22-EMBEDDING-DIST

## Implementation summary

Attempted to port catch22's `CO_Embed2_Dist_tau_d_expfit_meandiff`
(exponential-fit misfit of 2-D embedding distances) from the paper's and
hctsa's published definition, never from the GPL-3.0 reference
(`pycatch22` 1.0.2). Built a candidate implementation (z-score, delay `tau`
via `CO_FirstZero('ac')`, 2-D embedding, consecutive Euclidean distances,
moment-matched exponential fit, histogram comparison) and calibrated it
against `pycatch22` used strictly as a black-box oracle (never read as
source, never imported by any shipped file) — the same technique this
fork's existing `c22_ami2` and `c22_acf_first_min` ports use to settle
details the public definition leaves open.

The calibration did not converge: across 25 mixed synthetic frames, 30
histogram-parameter variants on 8 delay-pinned frames, a 21-point fine bin
sweep of the closest of those 30, 4 alternative distance/comparison
structures, and a generalisation cross-check of the closest reading
against the 25-frame set, no configuration reproduced the oracle's output
to anywhere near its own float precision (best: max error ~0.02-0.06,
plateauing rather than shrinking). Concluded Gate A (correctness) is
UNRESOLVED and this is a **measured revert**: no
`pandas_ta/statistics/c22_embedding_dist.py`, no
`tests/test_c22_embedding_dist.py`, no `Category`/`core.py`/README entry.

Artifacts: `docs/C22EmbeddingDistMeasured.md` (receipt),
`docs/measure_c22_embedding_dist.py` (calibration harness, reproducible via
`python docs/measure_c22_embedding_dist.py`).

Verified: `python -m pytest -q tests/test_readme_counts.py
