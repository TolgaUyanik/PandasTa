## Findings

### CRITICAL
- **pandas_ta/candles/clv_abs.py:24-28 and :55-57; docs/ClvAbsMeasured.md:37-46 (Decision 2); tests/test_altport2_ports.py:196 (CATEGORY_TOTAL comment); docs/MLCompanionContract.md:27; tests/test_clv_abs.py:14** — The receipt says "`ta.sma` returns `na` while an `na` is inside its window" and calls this "the source's behaviour, not a choice made for the feature". Nothing in the repo backs that: a grep finds the sentence only in these two new files, with no citation, no Pine run and no reference quote. As the reviewer remembers the Pine v5/v6 reference for `ta.sma`, it says the opposite: "`na` values in the `source` series are ignored; the function calculates on the `length` quantity of non-`na` values." The reviewer could not check this offline, so treat it as likely, not confirmed. If it holds, the port does not match its source. One flat bar blanks 14 outputs, and on seed 4 this blanks 504 of 2,000 bars (25%); the reviewer confirmed the NaN mask is exactly the 13-bar warm-up plus 42 × 14-bar blanks. The NaN propagation is also presented as fact in four places. Only `x / 0 = na` is safe, because `0/0` gives NaN in pandas anyway.
  - Fix: Settle it against the TradingView `ta.sma` reference page and quote the exact sentence in the module docstring and the receipt. If the reference says na values are skipped, compute the mean over the last `length` non-NaN values, e.g. `vp_abs.dropna().rolling(length).mean().reindex(vp_abs.index)`, decide whether a flat bar carries the last value forward, and write that choice down. Then rewrite `_reference` to skip NaNs, change `test_zero_range_bar_blanks_exactly_length_bars`, and re-run the script for the Gate A/C/D tables. If the reference really says na propagates, keep the code but replace "Pine returns…" with the quoted, cited sentence. Either way, remove the unmeasured "source's behaviour" wording from all four places.
