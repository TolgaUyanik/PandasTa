# Task `ts-ac1-60` — log

**Scope.** Port tsfresh's `autocorrelation(x, lag=1)` of 60 simple returns as
`pandas_ta/statistics/ts_ac1_60.py` through Gates A–D, with the five wiring
touch points, a test module, `docs/measure_ts_ac1_60.py` and
`docs/TsAc160Measured.md`. Gate E and both repositories' suites are the
launcher's. Lane: main thread (see `00-manifest.md`).

## Implementation, in the order it happened

1. **Read the precedent before writing anything**: `CLAUDE.md`'s gate table
   and five-wiring-point table, the merged `ts_kurt_60` (#93) and `ts_c3_20`
   (#88) ports — module, test module, receipt, measurement script — and the
   `git show` of #93's two commits to see the shape a port is expected to
   have. Read the issue mirror `docs/issues/093-ts-ac1-60.md` and the screen
   prototype at `docs/issues/screen/ind_screen.py` (candidate `ts_ac1_60`).

2. **Found the decision the issue turns on.** The prototype is
   `corr(r, delay(r, 1), 60)` — a Pearson correlation of two 60-pair slices
   over 61 returns — and tsfresh's `autocorrelation` is not: it uses the
   window's single mean, the population variance and a `(n - lag)`
   denominator over 60 returns. The issue's "Gates owed" line says *Gate A
   starts from the source formula, not the prototype*, so the source formula
   ships and the prototype is priced as a variant (measured: Spearman
   0.988839, max |difference| 0.1013, 0 of 1,439 bars bit-equal). ASSUMPTION
   A1 in `00-manifest.md`.

3. **Wrote the module** with the numerator spelled through the identity
   `2uv = u² + v² − (u−v)²`, which keeps the window mean out of every
   difference. That was not a preference: against an exact `Fraction` oracle
   on a path whose returns have `|mean|/sd` = 1e5 this spelling is 2.1e-10
   out and the algebraically identical raw-sum expansion 4.1e-06.

4. **Wrote `docs/measure_ts_ac1_60.py`** (sections `a`, `b`, `cd`, `meaning`,
   `guards`, `cost`) and ran it before writing a single number into the
   docstring or the receipt. The module shipped with a placeholder docstring
   until the run existed.

5. **Two guards came out of the measurements, not out of taste.**
   * The variance floor is `(4096 eps)²`, not tsfresh's `np.isclose(var, 0)`:
     that guard is absolute at `atol = 1e-8` and empties every window whose
     return sd is under 1e-4 (measured: 0 of 240 windows of a σ = 1e-6 walk,
     where this column reports all 240 and reads ±0.27).
   * The accumulator trust test was added after the magnitude sweep showed
     that pandas' ONLINE `rolling.var`/`rolling.sum` leave a finite residue
     after a giant return has left the window: one planted return of 1e+8
     moved 139 bars that hold no part of it by up to 1.280, with no NaN to
     mark them. The test bounds both accumulators by exact algebra on the
     window's own range (deque-computed, therefore local) and turns those
     bars into NaN, at a measured cost of 0 bars on seven clean frames.
     ⚠ It is not a cure at every magnitude (1e+2 / 1e+4 / 1e+6 pass it at
     1.3e-09 / 3.3e-06 / 8.5e-03), which the receipt and the docstring say.

6. **Wiring**: the export, `Category["statistics"]`, the `core.py` accessor,
   `tests/test_ts_ac1_60.py`, then `README.md`'s three counts,
   `docs/MLCompanionContract.md`'s column-form counts,
   `tests/test_altport2_ports.py`'s `CATEGORY_TOTAL`, and
   `docs/IndicatorDictionary.md` regenerated by its own generator (which tags
   `TS_AC1_60` **SF**).

7. **Gate E not run**, per the session rules: the receipt says *pending, run
   by issue-solver after this session*, and
   `tests/test_ts_ac1_60.py::test_the_gate_e_ledger_carries_no_row_for_this_column_yet`
   asserts the ledger carries no row, so the screen's prototype figures
   cannot be mistaken for this column's measurement.
