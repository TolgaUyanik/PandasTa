# `_TEMPLATE.md` — the INDREF per-indicator page shape

Worked example: [`tvstop.md`](tvstop.md). **Read it before filling this in** — it is the reference
for how much evidence a section is expected to carry, and it is the only page that exists as of
INDREF-0.

This template exists so INDREF-1 can machine-fill the whole fork without inventing a second doc
shape. **The "~201" this line used to carry was already stale when INDREF-1 ran**: the live surface
is 224 names in `Category` / 232 accessor methods / 233 generated pages (INDREF-1, 2026-09-10 — see
[`README.md`](README.md) §1 for the definition of "shipped" those pages apply).
It matches the parent repo's family-doc convention
(`../Backtesting/docs/indicators/family-*.md`) — same section names (*What it measures* · *Columns*
· *Formula AS COMPUTED HERE* · *Causality* · *ML-suitability* · *BIST specifics* · *Mining track
record* · *Improvement ideas*), same citation discipline, same ⚠ / 🔴 markers. INDREF-0's extra
sections (*Provenance*, *Overlap*, *Reachability*, a *Gate ledger*) are additions, not a
replacement: a family doc folds those into the prose, a per-indicator page gives them headings.

## Non-negotiables

1. **MEASUREMENT LAW.** Every sentence containing *only, never, always, every, all, identical* or a
   specific count must correspond to a command that was actually run, and the page must name where
   the number came from. This is not style: 17 of 18 TVPTA candidates failed first review, almost
   none on the mathematics — they failed on claims written before they were measured.
2. **A field with no measurement carries the STUB TOKEN — one exact literal string, not a phrasing
   you choose.**

   ```
   STUB: not measured — fill from <path>
   ```

   That em-dash is U+2014 and the token is matched character-for-character by
   `tests/test_indref_pages.py::test_stub_token_is_used_verbatim`. `TBD`, `FIXME`, `XXX`, `n/a`,
   `unknown`, a bare `not measured`, and a lone `—` in a numeric table cell are all **rejected by
   the suite**, because each reads to a later editor as "nobody has looked" and to a generator as
   "safe to fill in".

   **This rule is enforced, not requested.** `tests/test_indref_pages.py` runs in the normal
   `pytest` suite. It cuts the page into **groups** — `§<section>#T<k>` for the k-th table in a
   section, `§<section>#P` for that section's prose and bullets — counts every
   provenance-bearing number in each, and requires the metrics block to declare that exact count
   against that anchor. Numbers exempt individually only if their cell/line carries the STUB token
   or an inline artifact citation.

   Three properties matter and each was an actual defect in an earlier round of this guard:

   * **Coverage is per GROUP with a COUNT, not per section.** Section-level coverage let one
     metrics row license every number in that section forever, so a fabricated row dropped into an
     already-registered section passed clean. With counts, adding OR removing a number fails.
   * **Prose is scanned.** An earlier version read only lines starting with `|`, which policed the
     machine-filled half of a page and left the human-written half — where fabrication actually
     happens — invisible. A bullet reading `measured Sharpe **2.41**, rho = 0.9912` passed.
   * **Orphan metrics rows fail.** A row naming a group that carries no number is padding, and
     padding is how a provenance block starts lying.

   The guard is verified to BITE, not merely to pass. Five controls, each of which must fail:
   fabrication inside a **registered** section · a number in prose · scientific notation
   (`3.47e-3`) · an integer percentage (`87 %`) · an invented metrics row (`@ made_up.csv`).
   Re-run them after any change to the guard; a guard that only ever passes is decoration.

   ⚠ **What it does NOT catch, stated so nobody over-trusts it:** it does not check that a cited
   artifact exists (gitignored CSVs legitimately vanish), it does not check that a value is
   CORRECT (`n=` catches an added number, never a wrong one), and it does not match bare small
   integers — `89 frames`, `33 cells`, `L71` — because flagging those would train authors to
   ignore the test.

   Why a test and not a convention: the parent repo already ran this experiment.
   `../Backtesting/CLAUDE.md:77` records that its knowledge-base v1 died because "the bookkeeping was
   all by hand and went stale faster than anyone could re-read it" — one week of review produced a
   count wrong by 13×, and the same tally was corrected in one file and left stale in three siblings
   four separate times. v2's single design rule is quoted there: **a number that cannot be
   regenerated by a script does not go on a page.** `../Backtesting/CLAUDE.md:84` then records that
   v2's own guard `verify_wiki.py` does not exist, leaving v2 "v1 with better intentions". INDREF-1
   emits 233 pages; a prose rule would be that mistake a third time.
3. **Artifact-availability check.** Before quoting a CSV, confirm it exists. Overlap artifacts live
   under `../Backtesting/backtest_results/<batch>/`, which is gitignored
   (`../Backtesting/.gitignore:14`) — they are routinely cleaned. If the CSV is gone, say so, name
   the durable record you are quoting instead, and give the re-run command (see `tvstop.md` §7.4).
4. **Citation convention (SR-1).** Code anchors are FUNCTION NAMES or Pine/C source line numbers,
   never a BARE Python line number. `module.py::function` is the preferred anchor; a Python line
   range is acceptable only as a suffix beside a function name the surrounding text also gives
   (`strategy_miner.py:84-88` alongside `exclude_exact`). Pine/C source line numbers are fine — that
   source is immutable. `IE:` = `../Backtesting/backtesting_engine/indicator_engine.py`,
   `SI:` = `.../speedy_indicators.py`.
5. **Every page ends with a `## 13. Provenance metrics` block** carrying the literal marker
   `<!-- indref:metrics -->` and rows shaped
   `| §<sec>#<T k|P> — <what> | n=<count> | @ <provenance> |`. The block ends at the next heading,
   so prose may follow it.

   **Provenance classes accepted in the `@` cell** — one of these, or the row fails:

   | class | when | example |
   |---|---|---|
   | an artifact path | the number was read from a file | `@ backtest_results/…/x_20260827.csv (MISSING)` |
   | a test anchor | a test pins it and you re-ran it | `@ tests/test_x.py::test_name — RE-RUN GREEN <date>` |
   | `QUOTED` | copied from a durable doc, no artifact | `@ QUOTED from ../Backtesting/docs/…md §6.5` |
   | **`DERIVED`** | **you computed it in-document from other cells on the page** | `@ DERIVED <date> from the flips/bars cells above; NOT in any CSV` |

   **`DERIVED` is not a formality and a generator will hit it constantly.** Any number an author
   works out — a rate times a span, a difference, a ratio of two measured cells — has *no*
   artifact, and attributing it to one is a fabricated citation sitting inside the provenance
   block. That is the failure these pages exist to prevent, so it is the one the format must make
   impossible to commit by accident. **Several rows may name the same anchor and their counts
   sum**, which is exactly how a group is split into a measured half and a `DERIVED` half.

   Where an artifact no longer exists on disk, write `(MISSING)` and name the durable record you
   quoted; `MISSING` is a provenance statement, not an excuse, and the re-run command belongs in
   the artifact-availability subsection.
6. **Deleting a column you built is the expected outcome, not a failure** — and the page must record
   it (`tvstop`'s `TVS_DIST`, `flag_breakout`'s `FLAG_POLE_ATR`, `range_profile`'s `RPO_OSC` were
   all built, measured, deleted). A deleted column gets a struck-through row in §2 and a subsection
   of its own in §7. That history is exactly what makes the page readable without the git log.

## Which sections a machine can fill

`docs/gen_indicator_dictionary.py` probes the live package on a synthetic 600-bar OHLCV frame,
computed twice (`df1`, and `df2` = the same frame with price ×137) and it therefore already knows,
per indicator:

| probe output | key in the generator | feeds template section |
|---|---|---|
| category, name | `ta.Category` loop | header table |
| has a `df.ta.<name>()` accessor | `rec["ext"]` | header table |
| inputs (O/H/L/C/V) | `inputs(sig)` | header table |
| params, **declared** | `params(sig)`, from `inspect.signature` | header table — ⚠ see below |
| emitted column names | `rec["cols"][i]["name"]` | §2 |
| ML form tag `SF / PX / PX2 / BIN / ORD / CONST / ??` | `classify()` (`gen_indicator_dictionary.py:89`) returns a **`(scale, warmup, range)` triple whose `scale` is a long string** → pass that string to `tag(scale)` (:216), which special-cases `scale.startswith("other")` → `"??"` before the `TAG` dict lookup. Indexing `TAG` directly raises `KeyError` on an `other(x…)` scale. | §2 |
| warm-up (index of first non-NaN) | `rec["cols"][i]["warmup"]` | header table |
| observed min/max **on the fixture** | `rec["cols"][i]["range"]` | §2 ⚠ *a fixture measurement, NOT a bound* |
| import/call breakage | `rec["error"]` | header table + the *Known breaks* note — **not** Gate F, which is a pytest pass count from an actual run |
| first docstring sentence | `summary(fn)` | §1 seed only — **not** an acceptable §1 |
| known non-causal columns | `LEAK_RULES` (currently `ichimoku` `ICS_*`, `dpo` `centered=True`) | §5 |

⚠ **`inspect.signature` is NOT the effective defaults, and on this fork's ports it is useless on its
own.** Every validated parameter is declared `None` and resolved inside the function body by a
`_validated_int` / `_validated_float` fallback — `tvstop` declares
`atr_length=None, mult=None, multm=None, vmax=None` (the `tvstop` row of
`docs/IndicatorDictionary.md` — grep it; that file is generated and renumbers on every added
indicator) while the
values the column names actually encode are `14, 3.0, 3.0, 0.3`
(`pandas_ta/trend/tvstop.py:337-340`). A generator emitting the signature alone will print `=None`
on all 233 pages and be technically correct every time. **The header table therefore carries two rows**
— *Params (declared signature)*, machine-filled, and *Params (effective defaults)*, **human**, read
from the `_validated_*` fallbacks and cited to the source. Do not silently substitute the effective
values into a row labelled as coming from `inspect.signature`; that contradicts the dictionary row
cited in the adjacent cell.

**Machine-fillable end to end:** the header table's *declared* rows, §2 columns + ML form, §5's
known-leak flag, and the pytest pass count in the §12 ledger's Gate F row.

**Machine-fillable from files outside the probe:**

| section | source of truth | how |
|---|---|---|
| §2 register verdict column | `../Backtesting/docs/knowledgebase/IndicatorMLRegister.md` | join on column name; copy the verdict **verbatim** |
| §3 provenance (file, line count, licence, Pine version) | `docs/pine/<id>-*.pine` + the module docstring | `wc -l` and `grep -c ''` the file, `grep '@version'`, `grep -i 'license\|©'` |
| §7 overlap ρ / n | `../Backtesting/scripts/analysis/measure_<name>_overlap_full.py` output CSVs | parse `<name>_overlap_*.csv`; if absent, quote the family doc / register and say so |
| §8 reachability counts | `<name>_reachability_*.csv` from the same harness | same |
| §9 BIST contamination | `<name>_contamination_*.csv` (`--stage 3`) | same |
| §10 mining track record | `../Backtesting/datastore/source/StrategyMaster.csv` + `backtest_results/` | `grep -c '<PREFIX>_' …StrategyMaster.csv` and `grep -rl --no-ignore-files '<PREFIX>_' …/backtest_results/` — **`--no-ignore-files` is mandatory**, the default `grep` there honours `.gitignore` |
| §12 ledger, Gate F | `python -m pytest tests/test_<name>.py -q` | run it, quote the pass count and date |

**Needs a human paragraph — do not attempt to generate:**

- **§1 What it measures.** The docstring's first sentence is a seed, not an answer. §1 must say what
  economic quantity the column carries and, where a column was *not* shipped, why. Compare
  `tvstop.md` §1 — "a rate limiter on stop travel", plus the consequence that the shipped pair
  reports *when direction changed, not what it is*. No probe can produce that.
- **§4 Formula AS COMPUTED HERE**, including every deliberate divergence from the source (the NaN
  handling, the reduced-vs-literal transliteration choice, unenforced UI slider bounds).
- **§6 ML-suitability** beyond the tag: what the column does at pathological inputs, what tolerance a
  consumer must carry, which readings are unsafe.
- **§7's mechanism paragraph.** A ρ is a number; *why* the column duplicates its neighbour is the
  part that stops the mistake being repeated.
- **§9's reading** of the contamination shape (suppression vs fabrication vs pinning) and whether any
  screen separates tainted frames from clean ones.
- **§11 Improvement ideas.**

**A page for an indicator with no measurement campaign** — the large majority: `ls
../Backtesting/scripts/analysis/measure_*overlap*.py | wc -l` returns **16** harnesses (re-counted
2026-09-10 by `docs/gen_indicator_pages.py`; it was 12 on 2026-09-07) against 233 generated pages,
and most harnesses cover a batch rather than one indicator — only `dtdb`, `fvg` and `tvstop` have a
harness named for them —
is still worth generating: header + §2 + §3 + §10 are all
machine-fillable, and §5–§9 become explicit stubs naming the script that would fill them. Say so at
the top of the page rather than letting the reader assume the gates were run.
