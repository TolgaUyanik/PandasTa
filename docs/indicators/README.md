## 1. What "shipped" means here

`TODO.md`'s INDREF-1 line asked for "all 201". That number was stale when this ran and it was
also ambiguous: this package has three indicator surfaces and they are all true at once. The
definition applied by the generator, and applied to every page below:

> **shipped** = every name registered in `pandas_ta.Category`, **plus** every indicator
> callable on the package that `Category` does not know about, **minus** `ma`.

`ma` is excluded because it is a moving-average *dispatcher*: it returns another indicator's
output and emits no column of its own. That is not a fresh judgement — `gen_indicator_dictionary.py`
already carries `SKIP = {"ma"}` and the dictionary lists `ta.ma` under *Not indicators*. The
unregistered ones get a page because a consumer can call them; their header table says in
terms that a `df.ta.strategy()` sweep skips them.

## 2. Measured vs stub

A page is counted **measured** if ANY of three things is true, and the union is what the
table below counts:

1. a dedicated overlap harness
   (`../Backtesting/scripts/analysis/measure_<name>_overlap_full.py`) exists for that
   indicator name;
2. one of the batch campaign documents in this directory's parent
   (`docs/AltportPortsMeasured.md`, `docs/CandlePatternsMeasured.md`, `docs/PineAlternatesMeasured.md`, `docs/TalibPortsMeasured.md`) names one of the indicator's emitted column names;
3. the page is hand-written (`tvstop.md`).

⚠ **The caveat on (2), stated once here rather than argued on 33 pages.** The campaign docs
name comparator columns as well as ported ones, so a column-name match proves a measurement
*mentions* this indicator, not that the campaign *ported* it. Each affected page says so and
points at the document; open it to see which. An earlier version of this index applied only
test (1) and therefore reported 3 measured / 230 stub, which understated the measured set by
an order of magnitude — `sarext`, whose Gate E is recorded at ρ +0.9850 over 408,075 bars in
`docs/TalibPortsMeasured.md`, was counted a stub. Matching on the FUNCTION name instead of
column names swings it the other way, to 47, by catching every comparator mention; the
column-name test is the compromise, and it is a compromise, not a proof.

⚠ **Five indicators (`beta`, `ht_trendline`, `hwma`, `mama`, `sarext`) raise under the
dictionary probe**, so they have no probed columns and test (2) falls back to their declared
stem. Their §2 tables are empty because the harness could not call them, NOT because they
emit nothing, and whether the same call fails for a real consumer is undetermined and
currently has no ticket.

## 3. What is machine-filled

Machine-filled from a real run: the header table's declared rows, §2 (columns, ML form,
warm-up, probe range, register verdict), §3's module length and first-appearance date, §5's
leak flag, §10's mining greps, §12's Gate F pass count. Owed by a human and stub-tokened: §1,
§3's source identification, §4, §6, §7, §8, §9, §11 and the *effective defaults* row.

The *effective defaults* row is stubbed on purpose. On this fork's ports every validated
parameter is declared `None` and resolved by a `_validated_int` / `_validated_float` fallback
in the function body, so `inspect.signature` reports `None` and quietly substituting the real
value into a row labelled "declared signature" would contradict the dictionary row cited
beside it.
